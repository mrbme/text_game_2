Overview

Orion 3033 is a type-only retro game that runs as a single page in this Next.js 16 app. The player is the captain of the mining ship O.S.S. ORION, guiding the stranded crew of the survey ship CASSIUS out of a cave system on LV-221 by text relay — visual comms are down, so every reply the player types is a message the crew acts on, while something hunts them in the dark.

The canvas above shows every screen: attract-mode title with animated starfield, ominous intro crawl, ship-OS boot sequence, and the terminal where the whole game plays out, plus its help, high-threat, fail, and win states. A standalone homage prototype of the boot screen lives at plans/orion-3033/boot-demo.html; its line script becomes lib/game/boot-script.ts.

Done means: npm run dev serves the complete loop — title → intro → boot → terminal — with a full authored campaign (3 acts, ~15 story nodes, 15–20 minutes) playable start to finish by typing; both endings reachable; runs are ephemeral — nothing persists and losing starts a fresh run; fully keyboard-playable; npm run build and npm run lint clean.

Non-goals for this cut: no backend, accounts, or route handlers; no persistence of any kind (settled below); desktop-first layout (mobile works but is not optimized); no LLM-driven dialogue (settled in Approach below); no i18n. Audio is the one genuinely open call — see Open Questions at the bottom.

Approach

The game is a small phase machine wrapping a data-driven story graph. All state lives in one GameState object driven by a pure reducer, so the UI components stay thin and the story is authored as data, not code.

Pure client SPA, zero new runtime dependencies. app/page.tsx renders a single 'use client' <Game /> component. No server actions, no API routes, no game-engine or animation library — and no three.js: the aesthetic is flat 8-bit, so the starfield, scanlines, flicker, and glow are pure CSS, and everything else is text. A WebGL scene would add hundreds of KB to fight the pixel look. The only additions are two Google pixel fonts self-hosted via next/font/google. Story text ships in the bundle (~15 KB).

Deterministic keyword parser, not NLP. Each story node declares keyword groups (['left', 'west']) that map to a reply and a next node. Global commands (HELP, STATUS, LOOK) are checked first. Unmatched input gets an in-fiction fallback ("say again? the signal is chewing your words"), so the game never breaks character. This keeps the campaign authorable, testable, and fully offline. If LLM-flavored dialogue ever becomes worth it, it would replace only fallback lines behind the same parser — no engine changes — but it is out of scope here.

Ephemeral runs: you either win or lose. No localStorage, no CONTINUE, no mid-run checkpoints. A run ends rescued or lost; SIGNAL LOST returns to the title and the next run starts clean. The mitigations for losing a run are built into the design: the campaign is 15–20 minutes, the threat meter telegraphs danger before it maxes, and the overrun node offers one last-ditch escape before the lost ending.

Story engine and data model

A story node is one cave chamber or story beat: the crew lines that arrive when it is entered, a look description for the global LOOK command, a label for the status bar, and the keyword matches that leave it. The reducer echoes the player line, short-circuits on ending nodes (rescued or lost, any input starts a fresh run — the Terminal also maps bare Enter on an ending node to the restart action), then tries global commands, then node keywords, applies any threat delta, and enters the next node.

Threat is a 0–5 meter — noisy choices raise it, stealth choices lower it, and at 5 the engine jumps to the overrun node regardless of the route picked. Stats have explicit producers: wrongTurns increments on any match with a positive threatDelta, closeCalls on each threat overflow, elapsed time derives from startedAt (stamped when the terminal opens), and crew count is the constant 3.

A graph-validation bun test asserts that every match.next, START_ID, and OVERRUN_ID resolve to real nodes and that both endings are reachable — a typo in act data fails the suite, not minute nineteen of a playthrough.

17const bumpThreat = (s: GameState, delta = 0): GameState => {
18 const threat = Math.min(5, Math.max(0, s.threat + delta))
19 if (threat < 5) return { ...s, threat }
20 return enterNode({ ...s, threat: 3, closeCalls: s.closeCalls + 1 }, findNode(OVERRUN_ID))
21}

23const applyCommand = (s: GameState, raw: string): GameState => {
24 const input = raw.trim().toLowerCase()
25 if (input === '') return s
26 const echoed = append(s, 'player', raw.trim())
27 const node = findNode(echoed.nodeId)
28 if (node.ending) return initialState
29 const global = globalReply(echoed, input)
30 if (global) return global
31 const match = matchNode(node, input)
32 if (!match) return append(echoed, 'crew', node.fallback)
33 const wrongTurns = (match.threatDelta ?? 0) > 0 ? echoed.wrongTurns + 1 : echoed.wrongTurns
34 const replied = append({ ...echoed, wrongTurns }, 'crew', match.reply)
35 const after = bumpThreat(replied, match.threatDelta)
36 return after.nodeId !== replied.nodeId ? after : enterNode(after, findNode(match.next))
37}

46export const gameReducer = (s: GameState, action: GameAction): GameState => {
47 if (action.type === 'command') return applyCommand(s, action.input)
48 if (action.type === 'restart') return initialState
49 const phase = PHASE_ORDER[Math.min(PHASE_ORDER.indexOf(s.phase) + 1, 3)]
50 if (phase !== 'terminal') return { ...s, phase }
51 return enterNode({ ...s, phase, startedAt: action.now ?? 0 }, findNode(START_ID))
52}

  • L36-37 Overflow detection bumpThreat jumping to overrun CHANGES nodeId, so comparing against replied.nodeId detects the jump — and a player already standing in overrun can still escape via match.next. Unit-tested in the engine stage.

Visual treatment

Two self-hosted Google fonts: Press Start 2P for the title and headers (--font-pixel), VT323 for all terminal text (--font-terminal) — swapped into app/layout.tsx in place of the Geist pair. The CRT look lives entirely in app/globals.css, and the boot screen follows the late-80s/early-90s BIOS homage proven out in boot-demo.html: white VGA text on black, staged line reveals, a memory-test count-up, "Detecting…" probes that resolve after a beat, and the Deep Range Star badge.

The boot phase renders in BIOS white (--crt-bios) for authenticity, then the terminal phase switches to phosphor green — the palette shift doubles as a story beat: the ship's general OS hands off to the comms relay.

Accessibility is designed in, not bolted on: the terminal log is an aria-live="polite" region, the input is labeled and keeps focus for the whole game, every screen advances by keyboard alone, and prefers-reduced-motion disables flicker, starfield drift, and cursor blink while keeping the typewriter skippable via Enter. Log lines render as text nodes — never dangerouslySetInnerHTML — so story content can never inject markup.

VT323 gets hard to read small and pure-green-on-black can fail contrast at low weights. Mitigation: minimum 18px terminal text, contrast-check --crt-ink against --crt-bg (target ≥ 7:1), and run the ada-wcag-compliance audit before shipping.

A naive per-character setState across a long log can jank. Mitigation: only the newest line animates (older lines render as plain text), one interval at a time via use-typewriter, and Enter instantly reveals. If profiling still shows jank, batch reveals to 2–3 characters per tick.

Verification

Beyond npm run build, npm run lint, and the bun test suite (engine paths + graph validation), the real check is a full keyboard-only playthrough on npm run dev:

  1. Enter on the title → intro types out → Enter reveals, S skips → boot autoplays into the terminal.
  2. Type HELP, then STATUS, then LOOK, then gibberish — expect the command list, the status line with the location label, the chamber description, and an in-fiction fallback that restates the current choice.
  3. Play the golden path (level passage → quiet → hide → left → wait → flare) to the CREW SECURED ending with stats, then Enter — back to a fresh title.
  4. Start again; deliberately pick noisy routes until threat hits 5 — expect the overrun node's last-ditch choice, then SIGNAL LOST; Enter returns to the title and a completely fresh run (reload mid-game also starts fresh — nothing persists).
  5. Toggle prefers-reduced-motion in devtools — starfield, flicker, and cursor blink freeze; the game stays fully playable.

Review gates before commit: ada-wcag-compliance on the four screens, /mrbme-code-review on the diff.
